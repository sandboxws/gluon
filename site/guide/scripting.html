1

One-shots and pipes

gluon -e is the ruby -e shape: evaluate, print, exit. It takes Go and meta commands alike, so every inspector is a shell one-liner, and a pipe into gluon is the same engine with no banner.

{% session "scripting" "from a shell" %}

Repeated -e arguments land as one batch — one build — and every expression that prints, prints. A compile error goes to the terminal as it would at the prompt and the exit status says it failed, so a script can tell. None of it opens a scratchpad: a one-shot can neither inherit nor change the session you have open elsewhere.

What a script reads is the plain form, one line per value, and it is a compatibility surface: no setting reaches it — not {% setting "value.form" %}, not a theme, not a plugin's renderer — so a script written against it keeps working. Rendering has the difference.

2

JSON, for a program to read

-json prints one object instead of the plain rendering. An evaluation answers with its values, each with its type, kind and text; a meta command answers with ok, the command, and its text.

Every envelope carries ok, and an error comes back as JSON on standard output too, so nothing has to read standard error to find out what happened. ok says the command did its job, not what it found: an :impl that answers no is still ok, so a check reads the text. {% cmd ":query" "-json" %} answers with rows a program can read, and gluon doctor -json and gluon init -json answer with reports. The envelopes are compatibility surfaces, held to their shape by gluon's own tests.

Against a project

-host . attaches a one-shot to the module you are standing in, the way it attaches the REPL. The attach line goes to standard error, so standard output is only what the line printed.

4

In CI

Because the inspectors are one-liners with a stable output, a build can hold a property the compiler does not: that a hot struct stays packed, that a type keeps satisfying an interface, that a function stays inlinable.

justfilea struct that must not grow
# fails while reordering the fields would save bytes
check-layout:
    gluon -host . -e ':layout pricing.LineItem' -json \
      | jq -e '.text | test("reordering") | not'

# fails the day the service stops satisfying its generated interface
check-orders:
    gluon -host . -e ':impl *rpc.Orders, shopv1.OrdersServer' -json \
      | jq -e '.text | test("does not implement") | not'

A one-shot pays for the toolchain like any line that runs — a few hundred milliseconds warm — and the inspectors answered by the type checker pay for none of it. gluon doctor in a CI job reports the toolchain and module it found, and exits non-zero only when something gluon depends on is broken.
