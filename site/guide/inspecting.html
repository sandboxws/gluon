What is this

no build

The other half of a REPL: what is this, and what can it do. In a compiled language both answers are static, so most of what is on this page never builds or runs anything. It asks the type checker gluon already runs in its own process, and comes back in about a millisecond.

{% session "inspect-types" "the type checker, asked directly" %} {% shot "types" ":t and :m in a terminal — the pasted methods, and the interface they satisfy" %}

{% cmd ":t" %} names the type of any expression — both values, when a call returns two. {% cmd ":t" "-v" %} adds what the type is underneath and its kind, and says when the value is a constant, because a constant is untyped until something gives it a type and that is often the surprise.

An interface is where static stops. What is inside r is not a fact about the program text, so :t r says it cannot know rather than guessing. {% cmd ":t" "-d" %} is the one question here that runs something: it evaluates the expression once and reports the dynamic type — and because it runs it, a call with a side effect has that effect.

What is in scope

{% session "inspect-scope" %}

{% cmd ":ls" %} is pry's ls: every variable, function and type the session has bound, with the types the checker already worked out, and the values _1, _2 and on hold, with the expression each came from.

What can it do

no build

{% cmd ":m" %} lists a type's method set and the interfaces it satisfies. The pointer-only methods are marked, because the rule that puts them in *T's set and not T's is exactly the one that trips people up.

{% session "inspect-methods" %}

Every method of a strings.Builder is on the pointer, so a Builder value satisfies nothing and a *Builder is a fmt.Stringer and an io.Writer. Satisfaction is checked against error, a few standard library interfaces, and every interface you declared this session — so :m Square answers whether it satisfies the Shape you wrote a minute ago.

Against one interface

{% session "inspect-satisfy" %}

{% cmd ":impl" %} asks of a type, {% cmd ":sat" %} of a value, and both answer against the interface you name — declared here, imported, or in the module you are attached to. A no names the method in the way and the signature the interface wants, and says when *T would have satisfied it though T does not, which is what the compiler's own error leaves you to work out.

{% cmd ":cast" %} separates two assertions Go reports very differently. One compiles and may fail when it runs — whether any(1) holds a string is a question about a value. The other can never succeed, because no value of the interface's type could hold the target; the compiler rejects it, naming a method you never mentioned, and :cast names it for you.

Interfaces, embedding, generics

no build

Three questions about declarations: who implements this interface, what does this embedding promote, and what does this generic accept.

{% session "inspect-iface" %}

{% cmd ":iface" %} lists an interface's methods and the types that implement it, directly and by pointer. The search covers what the session can name — its own types, the packages its program imports, the attached module's packages already loaded — and never the whole module cache, so it is fast; when it finds nothing it says how many types it searched, so "nothing implements it" cannot be mistaken for "nothing was searched".

{% cmd ":embeds" %} lays out what embedding brought in and from where. A method two embedded types both provide at the same depth is reported as ambiguous rather than resolved, because that selector does not compile: a bufio.ReadWriter has no Reset you can call, though both halves have one. {% cmd ":gen" %} reads a generic's type parameters and their constraints from the declaration, so a generic nobody has instantiated can still be asked what it would take.

Stand-ins

no build

{% cmd ":mock" %} writes a mock implementation of an interface — a struct with a function field per method — and {% cmd ":spy" %} one that also records every call.

{% session "inspect-mock" %}

Both print source and declare nothing. The mock enters the session only if you paste it, so it cannot collide with a name you already have, and it is ordinary Go you can move into a test file. The methods are the method set :m computes, promoted ones included.

A method whose field is unset panics and names itself. The alternative — returning zero values — is how a mock makes a test pass for the wrong reason: the assertion holds because nothing was called, and nothing says so. A spy's count is len of its calls rather than a second field, so the two cannot disagree.

Where it sits in memory

{% cmd ":slice" %} shows a slice's runtime header — pointer, length, capacity — and says when two slices are looking at the same memory.

{% session "inspect-memory" %} {% shot "layout" "a type of the project's own, at the prompt of a session attached to it" %} {% shot "slice" "the two slices over one backing array, and the append that writes through it" %}

That sharing is invisible in the printed values and obvious in the pointers, which is the whole point: y starts one element into x, so appending to y wrote over x[3]. Strings work too, with offsets in bytes. :slice runs the session to read the headers, since pointers exist only at run time; they differ from one run to the next.

{% cmd ":layout" %} is the same kind of question answered entirely by the type checker, so it never builds: each field's offset, the padding between them, and the order that would waste least. The sizes and alignments are the compiler's for the platform gluon runs on — this page was recorded on a 64-bit machine.

Differences and error chains

{% cmd ":diff" %} reports only what differs between two values, each difference with the path to it. {% cmd ":err" %} lays a wrapped error chain out flat, one level per line.

{% session "inspect-diff" %}

Two structs of a dozen fields that differ in one produce one row, which is the reason to have :diff rather than print both and read them. A difference in shape is reported as one — different types stop the comparison there instead of calling every field different, and a length or a missing key is stated as itself. Both values come from one evaluation, so anything non-deterministic is compared against the same run it came from.

%w is Go's error idiom, and every level of a chain is something errors.Is and errors.As can match, so :err shows each level's dynamic type beside its message. A joined error shows every branch.

Documentation

{% cmd ":doc" %} is go doc at the prompt, and {% cmd ":doc" "-src" %} prints the implementation — pry's show-source. Three more flags cover what go doc has no answer for.

{% session "inspect-doc" %} {% shot "doc-src" ":doc -src, highlighted as the prompt highlights Go" %}

{% cmd ":doc" "-examples" %} reads a package's runnable examples off disk, each labelled with the identifier it demonstrates. go doc does not report them, and for much of the standard library they are the documentation. A package whose sources were never downloaded says so, rather than reporting that it has none.

{% cmd ":doc" "-url" %} prints the pkg.go.dev address at the version your build list has, so the page you open is the code the session runs — and when it cannot tell, as here with no module requiring uuid, it says the address is the latest rather than yours. It prints and does nothing else: no fetch, no browser. {% cmd ":doc" "-pkg" %} reads the name as a package, for a name that is also a symbol. Output longer than a screen is paged at the prompt and printed whole through a pipe.

What the release you are on brought

offline

Every Go distribution ships its own release record: $GOROOT/api/go1.N.txt lists release N's standard library additions, each with the proposal that accepted it, and $GOROOT/doc/godebug.md the behaviour changes and the setting that reverts each. {% cmd ":since" %} reads those, so it describes the toolchain you have and needs no network.

{% session "inspect-since" %} {% shot "since" ":since at a prompt, where it opens a view" %} {% shot "since-127" ":since 1.27, one release's changes" %}

The arrow marks the go directive this session builds at — the attached module's, when there is one, which is not always the toolchain's. The language column tells three states apart that a dash would run together: a count for a release somebody wrote notes for, none for one checked and found unchanged, and N gated for one nobody has written up, where N is how much syntax the type checker in $GOROOT/src/go/types admits only from that version.

:since 1.27 opens one release: its language changes, its GODEBUG entries and its additions a package at a time. {% cmd ":since" "-lang" %} is the language notes alone, each with a snippet the build tests compile at the version it claims and reject one below. {% cmd ":since" "-pkg" %} asks the other way round — every addition to one import path, across releases, which is how you find out when maps.Keys arrived.

{% cmd ":since" "-run" %} evaluates a note's snippet into the session. Loop variables are worth running under :use on an older module, because that change is not a compile error below its directive: the same three lines print [2 2 2] at go 1.21. A note that needs a newer go line than the session builds at is refused with which of the two numbers is short.
