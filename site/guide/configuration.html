Every setting, from the prompt

{% .Reg.Counts.Settings %} settings

{% cmd ":settings" %} with nothing lists every setting gluon has — what it does, what it is now, what it would be otherwise, what it accepts, and whether the value came from your file or a default. With a key it explains one; with a key and a value it changes it; with - it puts it back.

{% session "config-settings" %} {% shot "settings" ":settings at a prompt, filtered with /value" %}

At the prompt the list opens in a view you can filter with /, and enter opens a setting: what it is for, what it is now and where that came from, then the values it takes or a line to type one into. Choosing submits the same :settings key value you could have typed, checked by the same validator. Through a pipe the whole table prints.

A change writes exactly one line of config.toml and leaves every other byte — your comments included — as it was, and it is checked twice before it is written: that one line moved, and that the file still loads and reads back as what you asked. A setting that takes effect now says so; one that the next run reads, like {% setting "banner" %}, says that. {% setting "imports" %}, {% setting "database" %}, {% setting "hosts" %} and {% setting "plugins.disable" %} are listed and not settable here: they are arrays, and rewriting one wholesale would take the comments inside it, so they show what they hold and say where to edit them.

2

config.toml

~/.config/gluon/config.toml — or under $XDG_CONFIG_HOME — and every line of it optional.

TOML~/.config/gluon/config.toml
# Names a line may use without gluon running goimports to find them.
# An import nothing mentions is never written, so this costs nothing.
imports = ["strings", "slices", "maps"]

editor  = "nvim"     # or "builtin", gluon's own
timeout = "45s"      # how long one evaluation may take
banner  = "compact"  # full, compact or off

[input]
mode = "vim"

[value]
items = 500     # elements of one collection, described

[value.form]
default = "table"
list    = "columns"   # a list of structs, a column per field

[theme]
name   = "gruvppuccin-mocha"
string = "#A9B665"      # one role, over whatever the theme says

# Extra imports whenever the session is attached to this module.
[hosts."example.com/shop"]
imports = ["example.com/shop/internal/pricing"]

{% setting "imports" %} is the one worth setting: preloads are a name-to-path map, not lines written into every program, so an unused one is not an unused import — it is not an import — and a used one skips the goimports pass, about a hundred milliseconds off the line that names it. An unknown key is an error rather than a shrug, because a typo in a config file is otherwise invisible — a misspelled theme role included. The settings reference has every key, its default and what it accepts.

The startup screen

gluon opens on the wordmark, the versions, and a row for each thing the session starts with: the scratchpad and what it restored, the module it is attached to, the database it was configured to reach, the plugins the project's build list turned on, and the theme.

A row appears only where there is something to say, so a bare directory on defaults shows one and a project shows as many as it has facts. The plugins are the ones this project's build list turned on, not the standard library's, which every session has. The theme is named only when it is not the default. Nothing on the screen costs a build; opening a scratchpad does, so its row says opening… and becomes the answer where it stands.

{% setting "banner" %} is full, compact — the version and the hints — or off. Below sixty columns the wordmark drops on its own and the rows stay. A piped script, gluon -e and gluon mcp print none of it.
