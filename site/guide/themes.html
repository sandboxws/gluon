1

Choosing one, while looking at your own code

{% .Reg.Counts.Themes %} themes

Go source is highlighted everywhere gluon shows it — the line you are typing, the line echoed into scrollback, :src, :doc -src, :test, :mock — and SQL, JSON and TOML where a command answers in them. {% cmd ":theme" %} chooses the palette.

{% session "themes" %} {% shot "theme" "the chooser, on the theme in use" %}

At the prompt, bare :theme is a picker, and moving the selection does not draw a swatch beside the list — it installs the theme, so the prompt, the highlighting, the tables and the picker itself are all the palette being considered. enter keeps it, writing [theme] name into config.toml so the next session starts in it; esc puts back the one you opened with. :theme <name> does the same without the picker.

go is the default — violet keywords, green strings, cyan types — and go-light is the same palette for a white terminal. terminal is your own sixteen ANSI colours, which is what gluon looked like before it had a palette. Five are the dark half of Gruvppuccin; the other fifteen are converted from the editor themes of the same names. Each is drawn in itself in the themes reference. The code on this site is drawn in go, and in gruvppuccin-mocha when the switch at the top of the page says Gruvppuccin.

2

Dark, light, or either

gluon paints foregrounds and never a background, because your terminal owns that — so it cannot tell whether yours is white, and a palette drawn for paper is pale smears on black. A theme therefore says which ground it was drawn for, and every list prints it.

{% session "themes-cli" "the same, from the shell" %}

either is terminal's answer and only its answer: its colours are your terminal's own sixteen, so they follow you onto either ground. A hex colour degrades on its own — to the nearest of 256 on a 256-colour terminal, the nearest of sixteen below that, and to nothing in a pipe. NO_COLOR turns all of it off.

3

Your own

A theme is a TOML file in ~/.config/gluon/themes, one colour per role; a role left out keeps the default.

TOML~/.config/gluon/themes/mine.toml
about      = "one line, printed by gluon theme"
appearance = "dark"   # optional here, required of a theme gluon ships

[theme]
keyword = "#C6ACD9"
comment = "none"      # leave the terminal's own foreground alone

A theme you almost like costs one line rather than a copy: a role set under [theme] in config.toml overrides whatever the chosen theme says. An unknown role is an error, because the alternative is a colour that silently stays the default. The roles are the sixteen gluon theme show prints.

4

From an editor theme you already like

gluon theme import converts a TextMate .tmTheme, a VS Code theme or an IntelliJ colour scheme into a gluon theme; the format is read from the bytes, not the extension.

Shellconvert, then choose it
gluon theme import ~/Downloads/Monokai.tmTheme

The mapping is lossy in one direction and cannot be otherwise: about a third of gluon's palette describes a terminal program rather than a highlighter, and no scope in any editor theme means "the reverse-i-search prompt" — so those roles keep gluon's own values, and the command prints which, role by role.

What it will not do is hand you a colour that is not one. ident is the editor's own foreground, not its variable accent, which painted a whole screen pink. A rule whose meaning is its background — invalid, ink on a red field — has said nothing once the field is dropped. A language's own rule does not answer a question about every language. And a colour that cannot be seen on the theme's own ground did not convert. The ground itself is read from the theme's background rather than its label, because a label can be wrong: Tokyo Night Light ships "type": "dark" over a near-white page.
