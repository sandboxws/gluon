Every setting

~/.config/gluon/config.toml

:settings lists these with what each is now; :settings <key> <value> writes one line of config.toml and leaves every other byte alone.

importsimports a line may name without a goimports pass

takes effect at oncelisted, not settable
defaultnone
acceptsimport paths

A preloaded import is not written into every program: it is a name-to-path map consulted only when a line actually names the qualifier. So one that goes unused costs nothing, and one that is used skips ~135ms.

an array — :settings writes one line, and rewriting a list wholesale takes the comments inside it. Edit config.toml, or use :get

editorwhat :edit opens, over $VISUAL and $EDITOR

takes effect at the next start
default$VISUAL, then $EDITOR, then a terminal editor on $PATH
acceptsa command with its flags, or builtin
e.g.code --wait

Both of those are commonly unset, which is the only reason this exists.

builtin is the one value that names no program: gluon's own full-screen editor, with vim keys, a check key and a key that runs what you wrote without closing it. It is read from here alone — an exported $EDITOR does not veto it, because whether to launch a program is not a question anyone answers with an environment variable.

timeouthow long one evaluation may take

takes effect at once
default30s
acceptsa Go duration, positive
e.g.2m

The whole session replays on every line, so this bounds the replay and not just the newest expression.

bannerhow much the startup screen says

takes effect at the next start
defaultfull
acceptsfull, compact, off
fullthe wordmark, and a row for each thing the session starts with
compactone line — the version and the toolchain — and the hints
offnothing at all: the prompt, and that is it
e.g.compact

full is the wordmark, the version beside it, and a row for each thing the session starts with: the scratchpad it landed in, the module it attached to, the database it can see, the plugins this project's build list activated. A row appears only where there is something to say, so a bare directory on defaults shows one row and a project shows as many as it has facts.

compact is the version and the toolchain on one line, and the hints line under it. off prints neither.

Below sixty columns the wordmark is dropped on its own, because it is a picture and a picture that wraps is torn in half. The rows stay: they are the half that is about this session, and they are thirty columns wide.

A scratchpad that could not be opened is reported whatever this says. A session that believes it is being saved and is not is the failure that whole feature exists to avoid, and it is not decoration to turn down.

Only an interactive session has one. A piped script, gluon -e and the MCP server print none of this whatever this says.

hostsper-module imports the host's own index cannot offer

takes effect at oncelisted, not settable
defaultnone
acceptsa table per module path

a table per module path, each holding a list — neither is one line

databasehow to reach a project's database, not its password

takes effect at oncelisted, not settable
defaultnone
accepts[[database]] blocks

an array of tables — `gluon init` writes one, and :db reports what it found

input.modehow the prompt reads keys

takes effect at once
defaultemacs
acceptsemacs, vim
emacsreadline bindings — ctrl-a, ctrl-e, alt-f, alt-b
vimmodal editing — esc commands, i inserts
e.g.vim

emacs is the readline subset gluon has always bound — ctrl-a, ctrl-e, alt-f, alt-b. vim adds a normal mode: esc commands, i inserts, and the motions, operators, counts and registers that go with them.

In vim mode k and j walk history, because a one-line prompt has no line above; ctrl-r is redo in normal mode and reverse search in insert; and u undoes your typing, where :undo drops a session entry.

The prompt says which mode it is in — gluon[i]> while you type and gluon[n]> while you command, in the colour theme.mode gives it.

It changes which keystrokes produce which line and nothing else. A pipe, gluon -e and the MCP server have no keyboard and are unaffected.

value.formthe shape a value is drawn in

takes effect at once
defaulttable
acceptstable, line, tree, columns, literal
tablea bordered table per collection
lineone line per value, however deep it goes
treeindented and borderless — the only form that shows nesting
columnsa column per field, for a list of structs of one shape
literalGo source you could paste into a test
e.g.tree

table is the bordered box gluon has always drawn. The others answer shapes it serves badly: columns gives a list of structs a column per field, tree recurses where a table cell truncates, line keeps a small value on its line, and literal is source you could paste into a test.

It changes what a terminal draws and nothing else: a pipe, gluon -e and the -json envelopes are frozen surfaces and never see a form.

value.itemshow many elements of a collection are described

takes effect at once
default200
acceptsa whole number, 1 to 100000
e.g.500

The child describes this many elements of one collection and reports how many it left out; every renderer already draws the shortfall. Raise it to see a long slice or map whole, rather than slicing it by hand.

A separate budget bounds the whole value — the thing that keeps one *http.Request from becoming a dump of its transport — and this does not move it. A large collection of large elements can still stop short of this number.

It reaches the child in its environment, so a shell that already exports GLUON_MAX_ITEMS sets it for a session that never asked.

value.depthhow many levels of a value are described

takes effect at once
default6
acceptsa whole number, 1 to 100000
e.g.10

How far into a nested value the child describes structure before falling back to a flat line. A pointer unwrap does not consume a level, so this counts composites and not indirections.

A separate budget bounds the whole value and this does not move it, so a deep value may still flatten before this number. Cycles are detected independently, so raising it cannot turn a linked list into nonsense.

It reaches the child in its environment, so a shell that already exports GLUON_MAX_DEPTH sets it for a session that never asked.

scratch.padthe scratchpad an interactive session lands in

takes effect at the next start
defaultdefault
acceptsa scratchpad name, or - for none
e.g.notes

A scratchpad is a named session on disk, so the lines you were in the middle of are still there tomorrow. - or off starts in none, which is the persistent form of gluon -no-scratch: a scratchpad puts what you typed on disk, and that is a decision worth being able to write down.

Only an interactive session lands in one. gluon -e, a piped script and the MCP server open none whatever this says.

theme.<role>one colour, on top of whichever theme is on

takes effect at once
defaultwhatever the chosen theme says
acceptsa hex triple (#5fafd7), an ANSI number (6), or none
e.g.#5fafd7

A role is a thing gluon paints, not a place: keyword, string, error and the thirteen others :theme's picker shows in their own colour.
