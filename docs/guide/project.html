1

Attaching to the module you are standing in

A REPL that reaches only the standard library is a toy. :use attaches the session to a Go module — or start with gluon -host . — and then its packages import, including the ones under internal/, which is usually the interesting half.

gluonin ~/src/shop, a small service with an API, a database and a gRPC server
gluon> :use .
attached to example.com/shop (go 1.26.0) at ~/src/shop
10 importable package(s): api, app, cli, config, events, migrate, pricing, rpc, shopv1, store
gluon> pricing.Total(pricing.Sample()).String()
(string) "56.14" len=5
gluon> :layout pricing.LineItem
pricing.LineItem 56 bytes, align 8
╭────────┬───────────────────┬─────────────────┬──────╮
│ offset │ field │ type │ size │
├────────┼───────────────────┼─────────────────┼──────┤
│ 0 │ Gift │ bool │ 1 │
│ │ ← 7 bytes padding │ │ │
│ 8 │ Qty │ int64 │ 8 │
│ 16 │ Taxable │ bool │ 1 │
│ │ ← 7 bytes padding │ │ │
│ 24 │ SKU │ string │ 16 │
│ 40 │ Price │ decimal.Decimal │ 16 │
╰────────┴───────────────────┴─────────────────┴──────╯
reordering as SKU, Price, Qty, Gift, Taxable would be 48 bytes — 8 saved

The project in these guides is a small shop service: an HTTP API on chi, a gRPC server, a SQLite database behind sqlx, viper settings, a cobra CLI. Its source is in gluon's repository under testdata/shop, so every session here can be typed again against the same code.

Go allows a package under internal/ to be imported only by code under the path above it, so a module named gluon.local/session could never reach example.com/shop/internal/pricing. The rule is a prefix test on the importer's path, so gluon gives its temp module a path underneath the host's, and the test passes. It costs nothing a line: gluon still builds a one-file module, and the toolchain loads the import graph, not every package the project has.

Attaching changes what a bare name means — pricing is the project's — which is why it is asked for rather than automatic. :use -off detaches. gluon doctor reports what attaching would see: the module, its go directive and every package a session could import.

2

Where a line runs

Attaching makes the project's packages importable. It does not move the program: every line runs in the session's own directory, so a path your code opens relative to where you started gluon is not found there.

gluon> wd, _ := os.Getwd()
gluon> filepath.Base(wd)
(string) "gluon-session-2812318039" len=24
gluon> _, err := os.Stat("config.yaml")
gluon> errors.Is(err, fs.ErrNotExist)
(bool) true
gluon> v, _ := config.Load()
gluon> v.GetString("log_level")
(string) "debug" len=5

That is deliberate. gluon never writes into your project, and a line that creates a file would otherwise create it in your working tree, on every replay. The way code finds its files in production is the way it finds them here — an environment variable, a flag's default, a path resolved from a known root. The shop reads $SHOP_CONFIG, and resolves the paths in its settings against that file.

3

After you edit it

The session keeps what it derived from the project — the type checker's export data, the import cache, cached results — until you say the project changed. :reload says so, and :watch says it for you.

gluonthe tax rate edited in another window, between the two lines
gluon> pricing.TaxRate.String()
(string) "0.0825" len=6
gluon> :reload
reloaded ~/src/shop
dropped: the type checker's export data, the import cache, every cached result
10 importable package(s)
gluon> pricing.TaxRate.String()
(string) "0.09" len=4
gluon> :watch on
watching ~/src/shop — 14 Go file(s), every 300ms
gluon> :watch off
watching off — ~/src/shop is no longer polled

:reload drops every cached result and re-reads the project, and the next line is built against the source as it now is. :watch on polls the project's Go files and reloads when one changes; a change seen while a line is running waits until it finishes, and goes behind anything you typed ahead.

4

Adding a module

the only command that fetches

For anything the project does not already require, :get adds a module to the session. It is the one command that fetches a module, and bare, it lists what the session can build against.

gluon> :get
ariga.io/atlas v0.36.2-0.20250730182955-2c6300d0a3e1
entgo.io/ent v0.14.6
github.com/agext/levenshtein v1.2.3
github.com/apparentlymart/go-textseg/v15 v15.0.0
github.com/bmatcuk/doublestar v1.3.4
github.com/dustin/go-humanize v1.0.1
… 47 more lines
gluon> :get github.com/BurntSushi/toml@v1.6.0
added github.com/BurntSushi/toml v1.6.0
gluon> :toml config.Defaults()
features = ["gift-wrap"]
log_level = "info"
[http]
addr = "127.0.0.1:8765"
[grpc]
addr = "127.0.0.1:50051"
[database]
path = "data/shop.db"
gluon> :get -rm github.com/BurntSushi/toml
removed github.com/BurntSushi/toml v1.6.0

A module added with :get belongs to the session, never to the project: gluon does not edit your go.mod. Its packages are what their names mean from then on, ahead of any package of the same name elsewhere in your module cache. Adding one can activate a plugin — toml above, whose :toml writes a value as the document its tags produce; Plugins has all of them — and :get toml works too, because a plugin's short name is an alias for its module.

:get -rm drops a requirement and fetches nothing. It is refused while an entry still imports the module, naming the entry, and refused for a module the project itself requires. Without a version, :get takes the latest; with one, that version.

5

The environment, and the config files

:env is the process environment, and :conf a project config file — TOML, YAML or JSON — both with anything shaped like a secret masked.

gluon> :env SHOP
environment 2 matching "SHOP"
╭────────────────────────────┬─────────────┬──────────╮
│ variable │ value │ │
├────────────────────────────┼─────────────┼──────────┤
│ SHOP_ENV │ development │ │
│ SHOP_PAYMENTS_WEBHOOK_AUTH │ Bearer *** │ redacted │
╰────────────────────────────┴─────────────┴──────────╯
1 value redacted by shape — not a guarantee, and never by the key's name
gluon> :conf config.yaml
config.yaml 8 keys
╭───────────────────────┬─────────────────┬──────────╮
│ key │ value │ │
├───────────────────────┼─────────────────┼──────────┤
│ database.path │ data/shop.db │ │
│ features.0 │ gift-wrap │ │
│ features.1 │ loyalty │ │
│ grpc.addr │ 127.0.0.1:50051 │ │
│ http.addr │ 127.0.0.1:8765 │ │
│ log_level │ debug │ │
│ payments.provider │ acme-pay │ │
│ payments.webhook_auth │ Bearer *** │ redacted │
╰───────────────────────┴─────────────────┴──────────╯
1 value redacted by shape — not a guarantee, and never by the key's name

A value is hidden because of its shape, never because of its key's name: a bearer token, a password in a connection string, a vendor-prefixed key. PASSWORD_HINT=ask the team is not a password, and a redactor that hid it would be one people learn to work around — so the footer says how many values were hidden and that this is a judgement by shape, not a guarantee. A secret is never shown in part.

6

Requests

:http issues a request and renders what came back — the shorthand for the http.Get a line could always make.

gluonthe shop's API, served on 127.0.0.1:8765
gluon> :http GET http://127.0.0.1:8765/users/1
(*http.Response) 200 OK HTTP/1.1 99 bytes
╭────────────────┬──────────────────╮

(*http.Response) 501 Not Implemented HTTP/1.1 33 bytes
╭────────────────┬──────────────────╮
│ header │ value │

│ Content-Length │ 33 │
│ Content-Type │ application/json │

}

The method takes any case, and completes. :http -H adds a header and repeats for another, :http -d is the body, and :http -t how long to wait. Quote anything with a space in it: no shell has been near the line. A header may name a variable rather than carry one — -H 'Authorization: Bearer $TOKEN' resolves $TOKEN in the program that sends it, so the value reaches no history file, and a header whose value is shaped like a credential is refused, because by then it is already in the history.

A request made on a line is made again on every line after it, like any effect. :http is a command, not an entry, so it runs once, when you type it. gRPC has the same shape in :grpc.
