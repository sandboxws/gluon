1

Install

macOS · Linux · WSLamd64 · arm64

The one requirement is a Go toolchain on your PATH, because the toolchain is the evaluator: every line you type is compiled by the same go that builds your projects.

Shellno clone needed
go install github.com/sandboxws/gluon/cmd/gluon@latest

Or Homebrew — brew install sandboxws/tap/gluon — or a binary from the releases page. To build a checkout instead:

Shellfrom a clone
git clone git@github.com:sandboxws/gluon.git
cd gluon
go install ./cmd/gluon     # → ~/go/bin/gluon; `just install` is the same line

The module declares go 1.27.0, so that is the oldest toolchain that builds gluon — and the toolchain it builds your lines with is whichever go is on your PATH when you start it. If the shell cannot find gluon afterwards, go env GOBIN and go env GOPATH say where it landed.

Check the install

gluon doctor reports what gluon can see from where you ran it: the toolchain and its GOFLAGS, your config file, which plugins are active and why, and — inside a Go module — every package a session could import. It exits non-zero only when something gluon depends on is broken; standing outside a module is reported, not failed.

Shellverify
gluon doctor
gluon doctor -json | jq .      # the same report, for a script
gluon                          # and you are in
macOS: the 105ms you can delete

About 105ms of every line that has to run is macOS validating a Mach-O it has never seen — roughly a third of the wall clock, and nothing to do with Go. Adding your terminal under System Settings → Privacy & Security → Developer Tools removes it. gluon doctor times a freshly linked binary, so measure before and after rather than trusting spctl --status, which reports the global setting and not your terminal.

Shell completion and a man page come from the command tree itself: gluon completion zsh (or bash, fish, powershell) and gluon man. The gluon command lists every subcommand and flag.

2

The first session

Type Go. What comes back is the value, its type, and the facts about it you would otherwise print a second time to find out.

gluona value, and the truth attached to it
gluon> x := []int{3, 1, 2}
gluon> slices.Sort(x)
gluon> x
([]int) len=3 cap=3
╭───┬───────╮
│ # │ value │
├───┼───────┤
│ 0 │ 1 │
│ 1 │ 2 │
│ 2 │ 3 │
╰───┴───────╯
gluon> "héllo"[1]
(uint8) 195 (0xc3)
gluon> "héllo"
(string) "héllo" len=6 bytes, 5 runes

A slice says its length and capacity, because the two differing is where most slice surprises start. Indexing a string gives a byte, not a character: 195 is the first byte of the two that encode é, and the hex beside it is there because a byte is usually wanted as one. A string says how many bytes it is and how many runes, since those are different numbers the moment it leaves ASCII.

Values with structure are drawn as tables; a scalar stays on its line, because a box around the number 2 is worse than the number 2. Rendering covers the other shapes — a tree, columns, one line, or Go source you can paste into a test.

Every line re-renders the whole session into a genuine Go program and compiles it with your toolchain, so the semantics are the compiler's. Lines that do not need to run do not pay for that: an in-process type checker answers declarations, type errors and constant expressions in about a millisecond, without building anything. How it works has the numbers.

Started in a project with -host ., the startup screen says what gluon found there — the module it attached to, the database the project configures, the plugins its build list turned on — and the project's own packages import at the prompt, internal/ included. Your project covers attaching.

3

What it takes off Go

Nothing in that session imports slices, and nothing uses x after declaring it. Go rejects both. Scratch work breaks those two rules on every other line, so gluon removes them.

Go saysgluon does
declared and not usedwrites _ = x after every binding
undefined: fmtruns goimports, so you never type an import line
no new variables on left side of :=reads a retyped x := 1 as x = 1, the way irb would

It also prints the trailing expression with its type, which Go would reject as an unused value. None of this is hidden: :src shows the program your session actually became, rewrites included.

4

Carrying a value forward

it is the value the previous line printed — irb's _, which Go cannot spell because a bare underscore is the blank identifier. _1, _2 and on name every value the session has printed.

gluon> 2 + 2
(int) 4
gluon> "hi"
(string) "hi" len=2
gluon> it + "!"
(string) "hi!" len=3
gluon> _1 * 10
(int) 40

_N is a real variable. it is not: it is rewritten, when the program is rendered, to the _N that was newest where you typed it, so :src shows _2 + "!". That is forced by replay — the whole session is rendered again on every line, so a line that says it stays in the program long after it stopped being the newest, and each has to keep meaning its own predecessor, at its own type. :ls lists the values with the expression each came from.

5

Errors point at what you typed

The program gluon compiles is not the one you typed, but its errors are about the one you typed. Each entry is written with a line directive, so the compiler and the runtime both name your line and column rather than a file under a temp directory you never saw.

gluona compile error, and a panic
gluon> x := []int{1, 2, 3}
gluon> func f(a int) int {
...> return a + bogus
...> }
error: undefined: bogus
return a + bogus
^
gluon> x[10]
panic: runtime error: index out of range [10] with length 3
goroutine 1 [running]:
main.main()
x[10] +0x24
[exit status 2]
gluon> :undo
undone (1 entry left)
gluon> len(x)
(int) 3

The compile error is the type checker's, so it came back without a build, and a line that does not compile is never kept. The panic had to run to happen, and its traceback names the entry — x[10] — where a real one would name main.go:31.

A line that panics is kept, because it ran: the session is the program that ran it. Since the whole session replays on every line, it would panic again on each one after it, so gluon says that instead of going quiet — and :undo takes it back.

6

Pasting

A paste is echoed a construct at a time, exactly as typing would have echoed it, and evaluated as one batch: four lines cost one build, not four.

gluonfour lines pasted at once
gluon> type Point struct{ X, Y int }
gluon> func (p Point) Dist2() int { return p.X*p.X + p.Y*p.Y }
gluon> p := Point{3, 4}
gluon> p.Dist2()
(int) 25

A construct that spans lines — a function, a struct — accumulates into one entry however it arrives. When a paste does not end in a newline, its last line is left on the prompt rather than run, so you can read what you pasted before any of it happens. If one line of a batch does not compile, the batch is landed a line at a time instead, so the error belongs to the line that owns it and the others still run.

7

Help, for every command

Lines that start with a colon are gluon's own commands. :help lists them all; :help :layout is one command's page — what it takes, its flags, lines to try, and where it goes next — and --help after any command asks for the same page.

gluonone command's page, asked two ways
gluon> :help :layout
:layout <type>
field offsets, padding, and what reordering would save
type a struct type, or a value of one
examples
:layout struct{ a bool; b int64; c bool }
24 bytes, and the order that would take 16
Answers from go/types and never builds: sizes, offsets and alignment are
the compiler's own for the platform gluon runs on. The suggested order is
the one that wastes least padding, and the saving is stated in bytes.
see also :embeds :slice
tool go_layout, served without --eval
gluon> :t --helpopens a view
:t [-v | -d] <exp>
the type of an expression (Ruby's .class)
-v add the underlying type and its kind
-d run it once for the dynamic type inside an interface
examples
:t strconv.Atoi("12")
two values: (int, error)
:t -v time.Second
the named type, what it is underneath, and its kind
:t -d r
what is inside the interface r — this one costs a build
Answers from go/types in gluon's own process, so it never builds and comes
back in about a millisecond.
-d is the exception: it reports the dynamic type — what is actually inside
an interface value — which nothing but a run can know. It costs a build and
an execution, and it runs your expression, so a call with a side effect has
it. Only at the prompt: the MCP tool stays static and ignores the flag.
see also :m :ls :doc
also :type
tool go_type, served without --eval; -d only at the prompt

At the prompt, a page longer than a screen opens in a view that scrolls, and so does bare :help: a table of every command you can filter with / — by name, by flag, by what it does. Choosing one of a page's examples puts that line on the prompt without running it, so you can edit it first.

--help and ? ask for help on every command, and -h on every command whose argument is not Go — :t -h is the type of -h, because that is a Go expression. Asking is always safe: the question is answered before the command runs, so :undo -h drops nothing and :q -h does not quit.

While you type a command, the rest of its usage is drawn after the cursor, and tab completes its flags and their values — the themes :theme takes, the keys :settings knows, the methods :http sends. A command that comes from a plugin you have not activated still has a page: it names the plugin and the :get line that turns it on.

8

Leaving, and coming back

:q or ctrl-d quits. ctrl-c abandons the line you are typing and keeps the session.

Nothing is lost by quitting. gluon lands in a scratchpad called default and writes every entry down as you type it, so tomorrow's gluon replays it and you are where you were — the startup screen says how many entries came back. Scratchpads covers keeping several, and The session the commands that edit what one holds.

The history you search with ctrl-r is a different collection: every line typed on this machine, in one file under ~/.local/state/gluon. Editing a line has the keys.
