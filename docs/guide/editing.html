1

Completion from the type checker

12–22µs a keystroke

tab completes what the session actually knows, not a word list. The candidates come from go/types — what :t and :ls answer from — so a struct you declared two lines ago completes its own fields.

It completes names in scope, fields and methods, package members (strings.To), the packages you can name, and meta commands. tab accepts the ghost text, and ctrl-n/ctrl-p cycle when there is more than one.

Inside a composite literal it offers the fields not set yet, with the colon, because that is the next thing you type — and never a method, since Point{Dist: 1} does not compile. Inside a call it shows the callee's signature beside the line with the parameter you are typing in brackets, and offers the names whose type that parameter will take: the rule is types.AssignableTo, the compiler's own, so when nothing in scope fits, nothing is offered. The signature is a hint, never a suggestion — tab cannot accept it.

A meta command completes by what it declares it takes: its flags where a flag may go, and their values — :http g to get in the case you typed, :theme g to the themes that begin so, :scratch -rm to the scratchpads there are. The rest of its usage sits beside the line as you type, the way a signature does, and inside a flag's value it is that flag's help. Help has the rest.

2

Keys, and vim

The prompt reads keys the way readline does — ctrl-a, ctrl-e, alt-f, alt-b — until input.mode says vim.

KeyWhat it does
tab · ctrl-n · ctrl-paccept a completion · cycle through them
ctrl-rsearch every line typed on this machine
↑ ↓walk the history, a multi-line construct as one entry
ctrl-cabandon the line, keep the session
ctrl-l · :clearclear the screen, keep the session
ctrl-d · :qquit

With vim on, the prompt says which mode has the keyboard — gluon[i]> while you type, gluon[n]> after esc — and the cursor says it again in the two shapes vim draws: a block on a character in normal mode, an underline under one in insert. Both take the cell they are in, so nothing on the line moves when the mode changes, and every line starts in insert, so a mode left over from the last line can never swallow the start of the next.

vimnormal mode, at the prompt
i a I A          insert before, after, at the start, at the end
h l 0 ^ $        characters and line ends
w W b B e E      words; the capitals are whitespace-delimited
f t F T ; ,      to a character, and repeat
x X s S r D C    single-key edits
d c y + motion   operators, and dd cc yy for the whole line
p P              put, from one unnamed register
u ctrl-r         undo and redo of what you typed
2d3w             counts, and they multiply
k j              history, as ↑ and ↓ do

k and j walk history, because a one-line prompt has no line above and set -o vi binds them the same way. ctrl-r is redo in normal mode and history search in insert. o and O do not exist — the line is one line by construction — and an unbound key is a silent no-op rather than a character typed. Use ctrl-l or :clear rather than your terminal's own clear, which fights the renderer's cursor arithmetic.

3

Editing the session

:edit is pry's edit: it opens the entries — what you typed, not the program they render into — in your editor, and replaces the session with the file when it closes.

gluonthe marked lines are what was written in the editor
gluon> x := 2
gluon> y := x * 10
gluon> y
(int) 20
gluon> :editopens the editor
x := 3
y := x * 10
y
(int) 30
reloaded (3 entries)
gluon> y
(int) 30

If the edited session does not replay, the one you had is put back. The editor is editor if you set it, then $VISUAL, then $EDITOR, then a terminal editor on your PATH.

4

A buffer for more than a line

The prompt is one line. For twelve of them there is :buf, which hands the terminal to the same editor and runs the whole buffer as one evaluation when you close it.

gluon> :bufopens the editor
func greet(name string) string {
return "hello, " + name
}
greet("gluon")
(string) "hello, gluon" len=12
gluon> :buf -show
func greet(name string) string {
return "hello, " + name
}
greet("gluon")
gluon> :buf -check
buffer:1:6: greet redeclared in this block
func greet(name string) string {
^
session: other declaration of greet
func greet(name string) string {
^
gluon> :buf -clear
buffer cleared — 4 lines dropped

It is not :edit: the buffer is somewhere else entirely, starts empty, and running it appends to the session — which is why a -check after the run reports greet as declared twice: it is in the session now, and in the buffer too. What you write stays in the buffer between opens, so the loop is write, run, fix, run again; nothing of it reaches the disk when the session ends.

What the editor opens is a real main.go in a real module, with the session rendered around two regions marked for you to write in — one for declarations, one for statements — so your own gopls completes, hovers and checks against the x the session actually has. Write between the markers, not at the bottom of main: that is context, and an edit there is not taken — the answer says so rather than leaving you to wonder. :buf -check is the in-process type check, about two milliseconds and no build; it is an opinion rather than a gate, and :buf -run never asks it. :buf -show prints what gluon took, and :buf -clear empties it.

5

gluon's own editor

Handing the terminal to another program means gluon cannot draw while it has it, so the loop is write, quit, read, open again. editor = "builtin" is the other way: a full-screen editor of gluon's own that runs what you wrote and shows the answer underneath it.

KeyWhat it does
ctrl-erun it, and show the answer in a pane below, the editor still up
ctrl-kthe in-process type check, with a mark beside every line it names
ctrl-o · tabshow or hide the output · move into it to scroll
ZZ · ZQclose having run · close having not

The keys are vim's, and they are the prompt's own for everything on one line; a document adds j k gg G, o and O, linewise dd yy cc, and v/V with the operators. Running in place is offered where running replaces the session — :edit and :scratch -edit — so pressing ctrl-e twice leaves what pressing it once left. :buf appends, so there ZZ runs it once, on the way out. It is not a replacement for your editor, and external stays the default; it is for the machine that has none — a container, a fresh box, somebody else's server.
