1

What is this

no build

The other half of a REPL: what is this, and what can it do. In a compiled language both answers are static, so most of what is on this page never builds or runs anything. It asks the type checker gluon already runs in its own process, and comes back in about a millisecond.

gluonthe type checker, asked directly
gluon> x := []int{3, 1, 2}
gluon> :t x
[]int
gluon> :t "héllo"[1]
byte
gluon> :t strconv.Atoi("12")
(int, error) 2 values
gluon> type Celsius float64
gluon> :t -v Celsius(20)
Celsius constant 20
underlying float64
kind floating point
gluon> var r io.Reader = bytes.NewBufferString("hi")
gluon> :t r
io.Reader
an interface — print the value to see its dynamic type
gluon> :t -d r
static io.Reader, dynamic *bytes.Buffer pointer

:t names the type of any expression — both values, when a call returns two. :t -v adds what the type is underneath and its kind, and says when the value is a constant, because a constant is untyped until something gives it a type and that is often the surprise.

An interface is where static stops. What is inside r is not a fact about the program text, so :t r says it cannot know rather than guessing. :t -d is the one question here that runs something: it evaluates the expression once and reports the dynamic type — and because it runs it, a call with a side effect has that effect.

What can it do

no build

:m lists a type's method set and the interfaces it satisfies. The pointer-only methods are marked, because the rule that puts them in *T's set and not T's is exactly the one that trips people up.

gluon> type ByLen []string
gluon> func (s ByLen) Len() int { return len(s) }
gluon> func (s ByLen) Less(i, j int) bool { return len(s[i]) < len(s[j]) }
gluon> func (s ByLen) Swap(i, j int) { s[i], s[j] = s[j], s[i] }
gluon> :m ByLen
ByLen 3 methods
╭─┬──────┬─────────────────────╮
│ │ Len │ () int │
│ │ Less │ (i int, j int) bool │
│ │ Swap │ (i int, j int) │
╰─┴──────┴─────────────────────╯
satisfies sort.Interface
gluon> :m strings.Builder{}
strings.Builder 11 methods
╭──┬─────────────┬─────────────────────────╮
│ *│ Cap │ () int │
│ *│ Grow │ (n int) │
│ *│ Len │ () int │
│ *│ Reset │ () │
│ *│ String │ () string │
│ *│ Write │ (p []byte) (int, error) │
│ *│ WriteByte │ (c byte) error │
│ *│ WriteRune │ (r rune) (int, error) │
│ *│ WriteString │ (s string) (int, error) │

Every method of a strings.Builder is on the pointer, so a Builder value satisfies nothing and a *Builder is a fmt.Stringer and an io.Writer. Satisfaction is checked against error, a few standard library interfaces, and every interface you declared this session — so :m Square answers whether it satisfies the Shape you wrote a minute ago.

Against one interface

gluon> :impl *bytes.Buffer, io.Reader
*bytes.Buffer implements io.Reader
gluon> :impl bytes.Buffer, io.Writer
bytes.Buffer does not implement io.Writer
╭──────────────┬────────────────────────────────────╮
│ pointer only │ Write(p []byte) (n int, err error) │
╰──────────────┴────────────────────────────────────╯
*bytes.Buffer implements io.Writer — the method is declared on the pointer receiver
gluon> :sat os.Stdout, io.Writer
os.Stdout (*os.File) implements io.Writer
gluon> :cast any(1), string
any(1).(string) compiles
whether it succeeds depends on the dynamic type at run time
gluon> :cast io.Reader(nil), *strings.Builder
io.Reader(nil).(*strings.Builder) cannot compile
no io.Reader can hold a value of type *strings.Builder
╭─────────┬───────────────────────────────────╮
│ missing │ Read(p []byte) (n int, err error) │
╰─────────┴───────────────────────────────────╯

:impl asks of a type, :sat of a value, and both answer against the interface you name — declared here, imported, or in the module you are attached to. A no names the method in the way and the signature the interface wants, and says when *T would have satisfied it though T does not, which is what the compiler's own error leaves you to work out.

:cast separates two assertions Go reports very differently. One compiles and may fail when it runs — whether any(1) holds a string is a question about a value. The other can never succeed, because no value of the interface's type could hold the target; the compiler rejects it, naming a method you never mentioned, and :cast names it for you.

:iface lists an interface's methods and the types that implement it, directly and by pointer. The search covers what the session can name — its own types, the packages its program imports, the attached module's packages already loaded — and never the whole module cache, so it is fast; when it finds nothing it says how many types it searched, so "nothing implements it" cannot be mistaken for "nothing was searched".

:embeds lays out what embedding brought in and from where. A method two embedded types both provide at the same depth is reported as ambiguous rather than resolved, because that selector does not compile: a bufio.ReadWriter has no Reset you can call, though both halves have one. :gen reads a generic's type parameters and their constraints from the declaration, so a generic nobody has instantiated can still be asked what it would take.

4

Stand-ins

no build

:mock writes a mock implementation of an interface — a struct with a function field per method — and :spy one that also records every call.

gluon> :mock io.ReadCloser
// ReadCloserMock is a mock implementation of io.ReadCloser, generated by gluon.
// A method whose function field is unset panics naming itself, so an
// expectation nobody set cannot be mistaken for a real result.
type ReadCloserMock struct {
CloseFunc func() error
ReadFunc func(p []byte) (int, error)
}
func (m *ReadCloserMock) Close() error {
if m.CloseFunc == nil {
panic("ReadCloserMock.Close was called with no CloseFunc set")
}
return m.CloseFunc()
}
func (m *ReadCloserMock) Read(p []byte) (int, error) {
if m.ReadFunc == nil {
panic("ReadCloserMock.Read was called with no ReadFunc set")
}
return m.ReadFunc(p)
}
gluon> :spy io.Writer
// WriterSpy is a spy implementation of io.Writer, generated by gluon.
// A method whose function field is unset panics naming itself, so an
// expectation nobody set cannot be mistaken for a real result.
type WriterSpy struct {
WriteFunc func(p []byte) (int, error)
// WriteCalls holds one entry per call, in order.
WriteCalls []struct {
P []byte
}
}
func (m *WriterSpy) Write(p []byte) (int, error) {
m.WriteCalls = append(m.WriteCalls, struct {
P []byte
}{p})
if m.WriteFunc == nil {
panic("WriterSpy.Write was called with no WriteFunc set")
}
return m.WriteFunc(p)
}
// WriteCount is how many times Write was called.
func (m *WriterSpy) WriteCount() int { return len(m.WriteCalls) }

Both print source and declare nothing. The mock enters the session only if you paste it, so it cannot collide with a name you already have, and it is ordinary Go you can move into a test file. The methods are the method set :m computes, promoted ones included.

A method whose field is unset panics and names itself. The alternative — returning zero values — is how a mock makes a test pass for the wrong reason: the assertion holds because nothing was called, and nothing says so. A spy's count is len of its calls rather than a second field, so the two cannot disagree.

Where it sits in memory

:slice shows a slice's runtime header — pointer, length, capacity — and says when two slices are looking at the same memory.

gluon> x := []int{1, 2, 3, 4, 5}
gluon> y := x[1:3]
gluon> :slice x, y
╭───┬───────┬───────────────┬─────┬─────╮
│ │ type │ ptr │ len │ cap │
├───┼───────┼───────────────┼─────┼─────┤
│ x │ []int │ 0xfab5300ce20 │ 5 │ 5 │
│ y │ []int │ 0xfab5300ce28 │ 2 │ 4 │
╰───┴───────┴───────────────┴─────┴─────╯
x and y share a backing array — y starts 1 element into x
gluon> y = append(y, 99)
gluon> x
([]int) len=5 cap=5
╭───┬───────╮
│ # │ value │
├───┼───────┤
│ 0 │ 1 │
│ 1 │ 2 │
│ 2 │ 3 │
│ 3 │ 99 │
│ 4 │ 5 │
╰───┴───────╯
gluon> type P struct {
...> A bool
...> B int64
...> C bool
...> D string
...> }
gluon> :layout P
P 40 bytes, align 8
╭────────┬───────────────────┬────────┬──────╮
│ offset │ field │ type │ size │
├────────┼───────────────────┼────────┼──────┤
│ 0 │ A │ bool │ 1 │
│ │ ← 7 bytes padding │ │ │
│ 8 │ B │ int64 │ 8 │
│ 16 │ C │ bool │ 1 │
│ │ ← 7 bytes padding │ │ │
│ 24 │ D │ string │ 16 │
╰────────┴───────────────────┴────────┴──────╯
reordering as D, B, A, C would be 32 bytes — 8 saved

That sharing is invisible in the printed values and obvious in the pointers, which is the whole point: y starts one element into x, so appending to y wrote over x[3]. Strings work too, with offsets in bytes. :slice runs the session to read the headers, since pointers exist only at run time; they differ from one run to the next.

:layout is the same kind of question answered entirely by the type checker, so it never builds: each field's offset, the padding between them, and the order that would waste least. The sizes and alignments are the compiler's for the platform gluon runs on — this page was recorded on a 64-bit machine.

Differences and error chains

:diff reports only what differs between two values, each difference with the path to it. :err lays a wrapped error chain out flat, one level per line.

gluon> type User struct{ Name string; Age int; Tags []string }
gluon> got := User{"ada", 36, []string{"admin"}}
gluon> want := User{"ada", 37, []string{"admin", "ops"}}
gluon> :diff got, want
╭──────────┬───────┬───────┬──────────────╮
│ path │ got │ want │ │
├──────────┼───────┼───────┼──────────────┤
│ .Age │ 36 │ 37 │ │
│ .Tags │ len 1 │ len 2 │ length │
│ .Tags[1] │ — │ "ops" │ only in want │
╰──────────┴───────┴───────┴──────────────╯
gluon> :err fmt.Errorf("load config: %w", fmt.Errorf("open: %w", fs.ErrNotExist))
*fmt.wrapError load config: open: file does not exist
*fmt.wrapError open: file does not exist
*errors.errorString file does not exist

Two structs of a dozen fields that differ in one produce one row, which is the reason to have :diff rather than print both and read them. A difference in shape is reported as one — different types stop the comparison there instead of calling every field different, and a length or a missing key is stated as itself. Both values come from one evaluation, so anything non-deterministic is compared against the same run it came from.

%w is Go's error idiom, and every level of a chain is something errors.Is and errors.As can match, so :err shows each level's dynamic type beside its message. A joined error shows every branch.

Documentation

:doc is go doc at the prompt, and :doc -src prints the implementation — pry's show-source. Three more flags cover what go doc has no answer for.

gluon> :doc strings.Cut
package strings // import "strings"
func Cut(s, sep string) (before, after string, found bool)
Cut slices s around the first instance of sep, returning the text before and
after sep. The found result reports whether sep appears in s. If sep does
not appear in s, cut returns s, "", false.

gluon> :doc -url github.com/google/uuid.New

:doc -examples reads a package's runnable examples off disk, each labelled with the identifier it demonstrates. go doc does not report them, and for much of the standard library they are the documentation. A package whose sources were never downloaded says so, rather than reporting that it has none.

:doc -url prints the pkg.go.dev address at the version your build list has, so the page you open is the code the session runs — and when it cannot tell, as here with no module requiring uuid, it says the address is the latest rather than yours. It prints and does nothing else: no fetch, no browser. :doc -pkg reads the name as a package, for a name that is also a symbol. Output longer than a screen is paged at the prompt and printed whole through a pipe.

gluon> :since 1.27 -langopens a view
go 1.27 · generic methods
A method may declare its own type parameters, so a type can carry a generic
operation in its own namespace rather than forcing it out into a package-level
function. Box[int].Map to a Box[string] is the example everyone reaches for, and
until now it could not be a method at all: the receiver's type parameters were
the only ones a method was allowed, so Map had to become func Map[T, U any](Box[T], func(T) U) Box[U]
and read backwards.
The restriction was in the original generics design and was expected to be
temporary. What it cost was not expressiveness — the free function always
worked — but the ability to write a fluent chain, and to keep an operation on
the type it belongs to.
Needs go 1.27 — under a lower go directive the compiler rejects it.
Proposal: https://go.dev/issue/77273

return Box[U]{V: f(b.V)}
}

The arrow marks the go directive this session builds at — the attached module's, when there is one, which is not always the toolchain's. The language column tells three states apart that a dash would run together: a count for a release somebody wrote notes for, none for one checked and found unchanged, and N gated for one nobody has written up, where N is how much syntax the type checker in $GOROOT/src/go/types admits only from that version.

:since 1.27 opens one release: its language changes, its GODEBUG entries and its additions a package at a time. :since -lang is the language notes alone, each with a snippet the build tests compile at the version it claims and reject one below. :since -pkg asks the other way round — every addition to one import path, across releases, which is how you find out when maps.Keys arrived.

:since -run evaluates a note's snippet into the session. Loop variables are worth running under :use on an older module, because that change is not a compile error below its directive: the same three lines print [2 2 2] at go 1.21. A note that needs a newer go line than the session builds at is refused with which of the two numbers is short.
