What a plugin is

33 built in20 commands

A REPL that knows only the standard library treats every library the same, which means treating none of them well. A plugin teaches gluon one library: how its values read, and the questions worth asking of them. :plugins says which are active here, and why.

A plugin is inert until the session can see its library — in the project's build list, or added with :get — so a session with no gorm has no :sql, rather than a command that cannot work. A command whose plugin is not active still has a page: :help :sql names the plugin and the :get that turns it on. Activation is worked out when the build list changes, at :use and :get, never per line.

Plugins are compiled into gluon, and never link the library they describe. A plugin command rewrites its argument into Go source that the ordinary evaluator runs, transiently — the path :bench takes — so it can do nothing a line you could type could not, it leaves nothing in the session, and it uses the copy of the library your build list already has. :guide is a plugin's cheatsheet, for the one that ships one. The plugins reference lists all 33 with what each adds.

Renderers: a value as what it is

A uuid.UUID is sixteen bytes, and without a plugin it prints as sixteen small integers. A renderer draws it as what it is, wherever it appears — on its own line, or as a field of a struct.

gluon> 90 * time.Minute
(time.Duration) 1h30m0s = 5400s
gluon> events.Sample().Customer
(uuid.UUID) 5f0c2c1e-8a7b-4e0f-9c6d-3b2a1f0e9d8c v4 random, RFC 4122
gluon> sql.NullString{}
(sql.NullString) NULL
gluon> sql.NullString{String: "NULL", Valid: true}
(sql.NullString) "NULL"

A duration gets its total alongside its carry chain; a UUID its canonical form, version and variant; a sql.NullString reads NULL when it is one, and quotes the text when it is not, so the two cannot be mistaken for each other. *http.Response is a status line and a header table — Requests shows it — and a pgx pool's statistics are labelled counters instead of three depths of unexported fields.

Renderers see structure; commands see values. The program describes a value as JSON and gluon draws it, so a renderer can add up a duration — it has the number — but cannot read a time.Time, whose meaning lives in a String method the description walks past. So a time gets a command, :when, which asks the program, where the value is still real. Renderers apply in the terminal and nowhere else: a pipe and gluon -e print gluon's own plain form, byte for byte.

The shop builds its router with api.Routes(store), and the handlers read the store only when a request arrives — so a nil one is enough to list them. chi's walk descends into mounted sub-routers, so /admin's routes are there, and it hands over each handler without its name, so the handler column says it is unavailable rather than going blank. When a project requires two routers, the first in the registry's order answers and :plugins names the other.

5

gRPC and protobuf

:grpc with an address lists what a server exposes, through server reflection; with a pkg.Service/Method as well, it makes one unary call. :pb is a message's size on the wire and its text form.

A streaming method is listed and marked, because each line is a program that exits and a stream has nowhere to live — reading one message and hanging up would return a number that looks like an answer. The request in :grpc -d is checked against the reflected descriptor before the call, so a field you got wrong is named here and not by the server. :grpc -H adds metadata, and may name a variable instead of carrying a value; :grpc -t is the deadline, and :grpc -tls dials with TLS. Every call dials and hangs up, so what it measures is connecting plus the call, not gRPC, and no answer is cached.

A generated message prints as its Go struct — state, sizeCache and unknownFields included, the one view that says nothing about the message. :pb marshals it instead: the byte count is what the wire costs, and the text form is the descriptor's own view of the same value.

:migrations reads goose's tracking table, newest first, through the project's configured database — the connection :query uses, the same read-only allowlist, and never goose's own status call, which can create the table it is asked about. :migrations -d picks a database by name.

:expand is what sqlx's two rewrites do to a query: IN (?) flattened into as many placeholders as the slice has elements, a :name turned into a bindvar with the arguments reordered to match. They are pure functions over the text, so nothing is opened. :schema reads the table set ent generates — columns, keys, and the foreign keys its edges became — as descriptors the generated package already holds, with no connection.

:sql is the statement a gorm chain builds, and its arguments, in gorm's dry-run mode. Dry run has to be set at the start of a chain, so :sql parses what you typed and puts it there; nothing reaches the database, which is why a pool that has never connected is enough. The arguments are printed beside the statement rather than interpolated, because a query with its parameters substituted is not the query that runs. ent gets no :sql: its builders have no supported way to produce a statement without running it, and :guide ent says so.

:config is every key a viper — or koanf — instance resolved, and the value that won: from the file, the environment, a flag or a default. That precedence is what a config file cannot tell you, and why this is not :conf; values shaped like secrets are masked the same way. :yaml and :toml are the documents a struct's tags produce, through the copy of the encoder the build list has — TOML puts every scalar of a table before its first sub-table, which is where a key lands and the part the value cannot show.

:dec prints a decimal exactly, beside what float64 would have made of it. :services is what a samber/do or dig container has registered and in which scope, and :graph how the providers depend on each other — do learns an edge when it builds a service, so a service nothing has asked for shows —, which is not "no dependencies". :tree is a cobra command and everything under it, hidden commands marked rather than left out. :msgpack is the bytes a value encodes to, as a hex dump with the keys readable beside them.

8

Writing one

For a library gluon does not ship a plugin for, a TOML file in ~/.config/gluon/plugins/ adds commands — everything except renderers.

TOML~/.config/gluon/plugins/sqlc.toml
name    = "sqlc"
module  = "github.com/example/sqlc"
imports = ["github.com/example/sqlc"]

[[command]]
name    = ":sqlc"
arg     = "<query>"
summary = "the SQL a query builds"
rewrite = "{{.Arg}}.ToSQL()"
see     = [":query"]

[[command.example]]
line = ":sqlc db.Users().Where(\"id = ?\", 1)"
says = "the statement and its arguments"

rewrite is a template that produces Go source, so a TOML plugin has exactly the authority of a line you could type. A command can declare what it takes the way a builtin does — kind (go, name, words, sql or none) and [[command.param]], [[command.flag]] and [[command.example]] tables — and then it gets the same page, completion and usage hint a builtin gets. aliases, detail, text, a guide markdown file and [[alias]] short names for :get are the rest. An unknown key is an error, and [plugins] disable = ["http"] turns a plugin off.
