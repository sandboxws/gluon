Scratchpads

1

A session on disk

A scratchpad is a named session on disk. gluon lands in one called default, and every line you type into it is written down — the entries as you typed them, what is pinned, the host you were attached to and the modules the session added. Tomorrow's gluon opens it, replays it, and you are where you were.

gluonkeeping one, naming it, graduating it, showing it
gluon> :scratch parser-bug
scratchpad parser-bug — created, the session is empty
gluon> x := strings.Fields(" a b ")
gluon> len(x)
(int) 2
gluon> :scratchopens a view
scratchpads
╭──────────────┬───────────┬──────┬────────────────╮
│ scratchpad │ entries │ host │ last worked on │
├──────────────┼───────────┼──────┼────────────────┤
│ * parser-bug │ 2 entries │ — │ just now │
╰──────────────┴───────────┴──────┴────────────────╯
in parser-bug — every line lands in it · ~/.local/share/gluon/scratch
$ gluon scratch
parser-bug 2 entries
$ gluon scratch show parser-bug
x := strings.Fields(" a b ")
len(x)
gluon> :scratch -mv parser-fix
scratchpad parser-bug → parser-fix
gluon> :save
saved → ~/.local/share/gluon/scratch/parser-fix/main.go
gluon> :save -debug parser-fix
saved → ~/.local/share/gluon/scratch/2026-09-23-parser-fix/main.go
debug → cd ~/.local/share/gluon/scratch/2026-09-23-parser-fix && dlv debug
or open the directory — .vscode/launch.json is written beside the module
gluon> :shareopens a view
package main
import (
"strings"
)
func main() {
x := strings.Fields(" a b ")
_ = x
__gluonPrint(len(x))
}
enter uploads this to the Go Playground — nothing has been sent yet
gluon> :scratch -off
detached from scratchpad parser-fix — the session continues and nothing more is written down

:scratch on its own lists them — how many entries each holds, the host it records, when it was last worked on — and opens one from the view. :scratch <name> opens that one, creating it when it is new. :scratch -mv renames the one you are in, :scratch -rm shows one and asks before removing it, :scratch -edit opens its file, pins and all, and :scratch -off stops writing the rest of this session down.

Opening replays: the entries run as one program — one build for the whole session, not one per entry — so an entry that had an effect has it again unless it was pinned. Nothing is fetched: a recorded module comes from the local module cache, and one the cache no longer holds is named with the :get that would bring it back. A scratchpad that will not open is never written to; the file is left byte for byte as it was, and a :reset that shrinks one keeps what it replaced beside it in session.prev.

Only an interactive session opens one. gluon -e, a piped script and gluon mcp open none, so a tool call can neither inherit nor change the scratchpad you have open. gluon -scratch <name> starts in a named one, gluon -no-scratch in none, and scratch.pad is the lasting form of either.

2

Out of the REPL, into a module

:save writes the session out as a runnable module with its own go.mod, so gopls works in it — completion, hover, jump to definition.

Inside a scratchpad a bare :save refreshes the scratchpad's own program, so the module an editor or a debugger opens is the work in progress rather than a dated copy of it. :save <topic> writes a new dated scratch. :save -debug adds a debugger launch configuration beside the module and names the command that starts one from a terminal — gluon compiles each line into a program that exits, so there is nothing to pause, and the way to step through a call is a real debugger on a real module. :save -test puts what :test generated beside the program as a test file. gluon never writes into your project: all of it goes under ~/.local/share/gluon/scratch.

3

Showing someone

:share uploads the program :src shows to the Go Playground and prints the address it can be read at — the path that is otherwise save, open, copy, paste into a browser.

Public, and for good

The upload is public and cannot be withdrawn, so :share shows you the program itself and asks, every time. There is no flag and no setting that skips the question: a confirmation that can be pre-authorised is one that has stopped being asked. A program carrying anything shaped like a credential is refused outright, naming the line. Only the program goes — not the history, not the environment, and not the source of the module you are attached to.

Confirming needs a terminal. Through a pipe — and in the session above, which was recorded without one — :share prints what would have gone and uploads nothing.

4

From the shell

gluon scratch is the scratchpads from outside the REPL — what there is, what one holds, removing one. gluon new, run and watch are the other shape of scratch work: a small program in a file, when a prompt is not the right place.

Shella scratch program, from the shell
$ gluon new heap-sort -no-edit
~/.local/share/gluon/scratch/2026-09-23-heap-sort/main.go
$ gluon run -list
~/.local/share/gluon/scratch/2026-09-23-heap-sort
$ gluon run
~/.local/share/gluon/scratch/2026-09-23-heap-sort
hello
─ 282ms

gluon scratch show <name> prints what a scratchpad holds and evaluates none of it — there is no evaluator in that process at all, which is what makes that true rather than intended. Opening is not among its verbs, because opening a scratchpad is starting a REPL in it.

gluon new writes one directory per scratch with its own go.mod and opens it in your editor; -flat writes a single //go:build ignore file instead, which gopls greys out, so it is not the default. gluon run runs the scratch you touched last, or the one you name, and gluon watch runs it again on every save. The gluon command lists every flag.
